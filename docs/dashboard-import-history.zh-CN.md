# Dashboard 导入历史

[English](dashboard-import-history.md)

Dashboard 导入历史会记录成功写入至少一个事项的 GitHub、CSV、JSON 和 Markdown 导入。

打开项目后，从侧边栏进入 **导入历史**。每条记录会显示来源、批次标签、创建时间、
计划写入数、实际写入数、跳过数、状态映射数、外部链接数，以及该批次当前的活跃/
已删除事项数。

每条记录都有 **分诊批次** 链接，会打开按该导入批次标签筛选后的列表。之后即使离开
结果页，也可以重新回到同一批导入事项继续整理。

如果导入错了或重复了，可以使用 **软删除批次**。IssueDeck 会找到带有该批次标签的
活跃事项并批量软删除，同时保留导入历史记录，方便后续审计和回看。

如果误删了批次，可以使用 **恢复批次** 找回同一批次里已经软删除的事项。恢复操作
只针对已删除事项，不会重复创建仍然活跃的工作项。

当批次里没有可匹配的活跃或已删除事项时，删除和恢复按钮会自动禁用，方便先扫一眼
状态再操作。

历史列表上方可以按来源（`GitHub`、`CSV`、`JSON`、`Markdown`）和当前事项状态筛选
批次。比如只看已全部删除的导入以便恢复，或只看仍有活跃事项的导入继续分诊。

只预览不写入的导入不会记录；正式导入但写入 0 个事项的批次也不会进入历史。
